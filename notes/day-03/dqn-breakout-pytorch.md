## 中文精读导读 / Detailed bilingual reading guide

这份专题笔记研究的是一个“最短可读”的 Breakout DQN，而不是性能完整的 Atari 实现。阅读时应始终区分三层：

1. **算法概念：** replay buffer、epsilon-greedy、Bellman target、Q-network 和 gradient update。
2. **教学代码：** 为了短小而省略 target network、图像预处理、frame stacking、checkpoint 与系统评估。
3. **项目实现：** `dqn_boxing.py` 补回 Atari 训练真正需要的稳定机制。

一条 transition 写成

\[
e_t=(s_t,a_t,r_t,s_{t+1},d_t).
\]

中文逐项解释：\(s_t\) 是动作前画面，\(a_t\) 是执行的按钮，\(r_t\) 是这一步环境奖励，\(s_{t+1}\) 是动作后画面，\(d_t\) 表示 episode 是否结束。Replay buffer 保存很多这样的五元组，随机抽取 mini-batch 来训练。

Q-network 的输出不是概率，而是每个动作的长期价值。例如四动作输出 `[1.2, -0.4, 2.1, 0.8]` 时，greedy action 是 index 2，因为它的 Q-value 最大。epsilon-greedy 会偶尔忽略该最大值并随机探索，避免网络永远只重复早期偶然偏好的动作。

Bellman target

\[
y=r+\gamma(1-d)\max_{a'}Q^-(s',a')
\]

可以读成：“当前动作应值多少 = 现在得到的 reward + 下一状态最好机会的折扣价值。”`(1-d)` 是 terminal mask；结束后没有下一步，所以不能继续加未来价值。

**Target network（目标网络）** 不是第二个独立 agent。它是 online Q-network 的延迟副本，只负责产生较稳定的训练 target。**Replay buffer（经验回放池）** 通常放在 CPU，因为保存成千上万张图像；每次只把 sampled batch 搬到 GPU。把整个 buffer 放进 GTX 1650 Ti 显存既没有必要，也很容易耗尽显存。

收到的脚本把 `210x160x3` 图像直接 flatten，导致第一层参数与 replay 内存都很大。稳定 Atari DQN 通常先灰度化、缩放到 `84x84`、堆叠最近数帧，再用 CNN 提取空间与运动信息。Frame stack 很重要，因为单帧看不出拳头或球正在向哪个方向移动。

判断训练是否成功不能只看 loss。至少应同时检查：evaluation return、胜率或分差、epsilon、Q-value 范围、TD error、训练速度、checkpoint 能否重新加载，以及多个 seed 下的结果。Loss 下降只说明网络追上当前 target，不等价于 policy 更会玩。

## 2. DQN in one picture / 一张图理解 DQN

For each environment transition, the agent stores

\[
e_t=(s_t,a_t,r_t,s_{t+1},d_t),
\]

where \(d_t=1\) means the episode ended. Training repeatedly samples a random
minibatch from replay memory:

```text
state s_t
 -> epsilon-greedy action a_t
 -> environment gives r_t, s_(t+1), done
 -> store transition in replay buffer
 -> sample old transitions
 -> compute Bellman target
 -> update neural Q-function
```

The neural network approximates one value per action:

\[
Q_\theta(s)
=\begin{bmatrix}
Q_\theta(s,a_1)&\cdots&Q_\theta(s,a_{|\mathcal A|})
\end{bmatrix}.
\]

`Q(s,a)` means the expected discounted return after taking action \(a\) in
state \(s\) and then following the policy.

## 3. ReplayBuffer / 经验回放

### 3.1 Why store old transitions? / 为什么保存旧经验？

Consecutive Atari frames are highly correlated. Training only on the latest
transition would feed the network a narrow, ordered stream. `random.sample`
approximately breaks this temporal correlation and reuses data:

\[
\mathcal B
\sim\operatorname{Uniform}(\mathcal D),
\]

where \(\mathcal D\) is the replay buffer and \(\mathcal B\) is a minibatch.

The supplied `deque(maxlen=10000)` is a circular history: once full, appending
a new transition discards the oldest one.

### 3.2 Tensor shapes / 张量形状

One raw Breakout observation is

\[
s\in\mathbb R^{210\times160\times3}.
\]

For batch size \(B=32\):

| Tensor | Shape |
|---|---|
| `states` | \([32,210,160,3]\) |
| `actions` | \([32]\) |
| `rewards` | \([32]\) |
| `next_states` | \([32,210,160,3]\) |
| `dones` | \([32]\) |

### 3.3 Raw-frame memory cost / 原始帧内存开销

`to_tensor` converts every frame from `uint8` to `float32`. One frame then uses

\[
210\times160\times3\times4
=403{,}200\ \text{bytes}
\approx393.75\ \text{KiB}.
\]

Ten thousand unique float frames require approximately

\[
\frac{403{,}200\times10{,}000}{1024^3}
\approx3.75\ \text{GiB}.
\]

If states and next states are stored independently, the worst-case payload is
about \(7.51\) GiB before Python/container overhead. Consecutive entries in this
specific loop may share some tensor objects, but memory safety should never rely
on that incidental aliasing.

Professional Atari replay normally stores compact `uint8` frames on CPU,
resizes them (often to 84x84 grayscale), and only converts sampled minibatches
to floating point on the training device.

## 4. Q-network / Q 网络

The supplied network is:

```text
210 x 160 x 3 image
 -> flatten to 100,800 values
 -> Linear(100,800, 64) + ReLU
 -> Linear(64, number_of_actions)
```

For \(A=|\mathcal A|\) actions, its parameter count is

\[
100{,}800\times64+64+64A+A
=6{,}451{,}264+65A.
\]

Almost all parameters are in the first dense layer. Flattening destroys the
explicit 2D neighborhood structure: pixels next to each other are not treated
as locally related. A **Convolutional Neural Network (CNN，卷积神经网络)** is a
better inductive bias for images because it learns reusable local filters.

This dense model is useful pedagogically: the input-to-Q mapping is obvious.
It is not an efficient Atari architecture.

## 5. Epsilon-greedy policy / Epsilon 贪心策略

The code selects

\[
a_t=
\begin{cases}
\text{uniform random action},&u<\epsilon,\\
\arg\max_a Q_\theta(s_t,a),&u\ge\epsilon,
\end{cases}
\qquad u\sim U(0,1).
\]

`EPSILON=0.1` means roughly 10% random actions and 90% greedy actions throughout
all training. At initialization, however, greedy actions come from a random
network. Modern DQN practice usually starts near \(\epsilon=1\) and decays to a
small floor so the replay buffer first collects diverse behavior.

## 6. Selecting the Q-value of the taken action / 取出实际动作的 Q 值

The network returns all action values:

\[
\mathbf Q_\theta(s_i)
\in\mathbb R^{|\mathcal A|}.
\]

`gather(1, actions.unsqueeze(1))` selects one entry per batch row:

\[
q_i=Q_\theta(s_i,a_i).
\]

Example / 例子：if one row predicts `[1.2, -0.4, 2.1, 0.7]` and the stored
action is 2, `gather` returns `2.1`. It does not choose the current greedy
action; it retrieves the value of the action that actually produced the replay
transition.

## 7. Bellman target and terminal masking / Bellman 目标与终止遮罩

The supplied target is

\[
y_i
=r_i+\gamma(1-d_i)
\max_{a'}Q_\theta(s_i',a').
\]

If \(d_i=1\), then

\[
y_i=r_i,
\]

because an ended episode has no future return. `torch.no_grad()` prevents the
target branch from receiving gradients.

### Important simplification / 重要简化

The same network \(Q_\theta\) computes both the current prediction and the
bootstrap target. As \(\theta\) changes, the label \(y_i\) changes immediately.
This creates a moving-target feedback loop.

Standard DQN stabilizes this with a separate target network \(Q_{\theta^-}\):

\[
y_i^{DQN}
=r_i+\gamma(1-d_i)
\max_{a'}Q_{\theta^-}(s_i',a'),
\]

where \(\theta^-\) is copied from \(\theta\) only periodically.

## 8. Loss and optimization / 损失与优化

The teaching code uses Mean Squared Error (MSE，均方误差):

\[
\mathcal L(\theta)
=\frac{1}{B}\sum_{i=1}^{B}
\left(Q_\theta(s_i,a_i)-y_i\right)^2.
\]

The optimization sequence is:

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

- `zero_grad`: remove gradients left from the previous update.
- `backward`: compute \(\nabla_\theta\mathcal L\) by backpropagation.
- `step`: Adam updates parameters using those gradients.

Large Atari TD errors can make MSE gradients large. The project baseline uses
Huber loss (PyTorch `smooth_l1_loss`), which is quadratic near zero and linear
for large errors:

\[
L_\delta(e)=
\begin{cases}
\tfrac12e^2,&|e|\le\delta,\\
\delta(|e|-\tfrac12\delta),&|e|>\delta.
\end{cases}
\]

## 9. Environment loop / 环境交互循环

Gymnasium returns

```python
next_obs, reward, terminated, truncated, info = env.step(action)
```

The code correctly combines both ending conditions:

\[
done=terminated\lor truncated.
\]

- **terminated（自然终止）**: the task itself reached a terminal condition.
- **truncated（外部截断）**: a time limit or wrapper stopped the episode.

Each step then performs four conceptual operations:

1. choose an action;
2. interact with the environment;
3. store the transition;
4. sample replay and learn when at least 32 transitions exist.

## 10. Why the supplied code does not use GPU / 为什么原代码没有使用 GPU

Installing CUDA-enabled PyTorch only provides capability. The program must move
both model parameters and tensors to the same device. The supplied source never
calls `.to(device)` and creates CPU tensors, so it remains CPU-only.

The minimal pattern is:

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
agent = BreakoutAgent(env).to(device)

state = torch.as_tensor(obs, dtype=torch.float32, device=device) / 255.0
batch = batch.to(device)
```

All operands in one operation must share a device. A CUDA model with CPU input
raises a device-mismatch error.

The maintained `examples/dqn_simple.py` adds this device handling. However, it
also keeps replay frames as float tensors on the selected device. With 10,000
raw frames that can exhaust the GTX 1650 Ti's VRAM. Better design is:

```text
CPU replay buffer in compact uint8
 -> sample only one minibatch
 -> move minibatch to CUDA
 -> forward/backward
```

GPU use must be designed, not merely switched on.

## 11. What is intentionally missing? / 教学版本省略了什么？

| Missing mechanism | Why it matters / 为什么重要 |
|---|---|
| Target network | reduces moving-target instability |
| CNN | preserves local image structure and reduces parameters |
| Frame stacking | exposes velocity/direction hidden in one still frame |
| Real image resize/grayscale | reduces replay memory and irrelevant visual detail |
| Epsilon schedule | explores broadly before becoming greedy |
| Learning warmup | avoids training on the first tiny replay sample |
| Training frequency control | avoids necessarily updating after every step |
| Huber loss | reduces sensitivity to large TD errors |
| Gradient clipping | bounds unusually large updates |
| Random seeds | improves reproducibility |
| Checkpoints | preserves trained state and optimizer metadata |
| Separate evaluation | distinguishes exploratory training from greedy policy quality |
| Metrics | makes loss, return, epsilon, and Q-value stability inspectable |

These omissions do not make the file useless. They make it a **conceptual
minimum**: every major line maps directly to one DQN idea.

```text

```

This is the maintainable baseline for the course Boxing project.

### Broader algorithm evolution / 更广泛的算法演化

1. **Tabular Q-learning** stores one value per discrete \((s,a)\); images make
   the table impossible.
2. **Neural Q-learning** replaces the table with \(Q_\theta(s,a)\), enabling
   generalization but introducing instability.
3. **DQN** adds replay memory and a target network to stabilize neural
   bootstrapping.
4. **Double DQN** separates action selection and target evaluation to reduce
   maximization bias:

\[
y_i^{Double}
=r_i+\gamma(1-d_i)
Q_{\theta^-}\left(
s_i',\arg\max_a Q_\theta(s_i',a)
\right).
\]

5. **Dueling DQN** decomposes state value and action advantage.
6. **Prioritized replay** samples surprising/high-error transitions more often.

Newer does not automatically mean necessary. A reliable plain DQN baseline is
more useful than several extensions whose evaluation pipeline is not trusted.

## 13. Safe verification sequence / 安全验证顺序

1. Verify PyTorch and CUDA independently with a random CUDA tensor.
2. Compile/import the source without executing its `__main__` training block.
3. Instantiate the network with a fake Breakout-shaped observation/action
   space and verify output shape.
4. Add a tiny replay batch and run exactly one optimizer update.
5. Verify ALE and the Breakout ROM with one reset and one random step.
6. Only then start a short training smoke test.
7. Use `dqn_boxing.py`, not the raw teaching loop, for project experiments.

Do not begin by launching 100 episodes. Installation, ROM, shape, device, and
memory errors are much easier to diagnose separately.

## 14. Quick glossary / 术语速查

| Term | 中文 | Plain meaning / 简明含义 |
|---|---|---|
| Q-value | 动作价值 | Expected future discounted return of one state-action choice |
| Replay buffer | 经验回放池 | Stored transitions sampled in random order |
| Bootstrap target | 自举目标 | Target partly estimated by another Q prediction |
| Target network | 目标网络 | Slowly updated network used to calculate stable targets |
| TD error | 时序差分误差 | Difference between Bellman target and current Q prediction |

| Device | 计算设备 | CPU or a specific GPU holding tensors and parameters |
